# 安全性と利用範囲

ローカルの1人利用を対象とする。接続キーで利用者を認証する。利用者ごとの権限分離と外部公開の検証は未対応のため、インターネットへ公開しない。

## 実行する範囲

AIはVMやデスクトップコンテナを操作する。バックエンドは環境管理のためにDockerソケットを使う。バックエンドが侵害された場合までホストの隔離を保証する構成ではない。

API・状態通知・画面配信は認証を必須とし、ブラウザのOriginも制限する。ブラウザにはHttpOnly・SameSite=StrictのセッションCookieを渡し、接続キーをブラウザの保存領域やURLに残さない。セッションは12時間、ログアウト、バックエンド再起動のいずれかで失効する。APIクライアントはAuthorizationのBearerで接続キーを送れる。

VNC・ADBをホストへ直接公開せず、画面配信は認証付きプロキシを通す。旧版の中継は同じプロジェクトのものだけ起動時に撤去し、失敗した場合は起動を止める。既存環境に残るVNCの公開設定は、環境を再作成するまで残る。

管理用ネットワークと各作業環境の専用ネットワークを分ける。管理APIは管理用IPだけで待ち受け、送信元のネットワークも確認する。作業環境から別環境や管理APIへの接続を制限し、外部サイトへの接続は許可する。転送ヘッダーで送信元を偽装しても許可しない。

環境とネットワークは所属プロジェクトを確認して操作する。旧環境は保存済み情報と共有ネットワークの一致も確認し、専用ネットワークへ移す。移行や所属確認に失敗した場合は処理を止める。バックエンド再作成後は保存済み情報から接続を復元する。

## 実行と停止

1タスクは回復操作を含めて200アクションまでとする。回復の再試行と再計画にも上限を設ける。同じ環境への後発タスクは先行タスクを停止し、別環境では並列実行できる。

時間・モデル送信・使用トークンにも上限を設け、一時停止中とモデルの内部再試行、決定モデルにも適用する。使用量を取得できない応答では停止する。推定費用の上限は単価を指定した場合に使える。[設定と制約](../README.md#実行上限を変える)を確認する。

時間切れでは画面操作に停止を要求し、実行中の処理が終了してから接続を解放する。中断した操作は一部が実行された可能性も含めて履歴に残す。

AIによる環境の再起動は `allow_vm_restart=true` の場合だけ実行する。再起動はディスクを初期化しない。Web UIからタスクの一時停止・再開・停止ができる。黒い画面を検出するとウェイクを試みる。

## 保存する情報

操作、判断理由、時刻、処理時間、トークン使用量を履歴に保存する。入力した文字列も含まれる。秘密情報の自動マスキングは未実装のため、保存先とバックアップのアクセスを制限する。

履歴を保存できなければタスクを止める。VM情報の破損は上書きせずエラーを返す。固定QEMU VMと動的VMは、読み取り専用テンプレートから複製した専用ディスクを使う。

動的環境の削除ではディスクも削除する。バックアップする場合は対象環境を停止してからコピーする。

## 残る課題

利用者ごとの権限分離、秘密情報の保護、危険操作の承認、アクションレート制限を追加する。請求実績との照合、QEMUとAndroidの実機検証も残る。[確認事項](production-readiness.md)で追跡する。
