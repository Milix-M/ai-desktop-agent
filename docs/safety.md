# 安全性と利用範囲

ローカルの1人利用を対象とする。接続キーで利用者を認証する。利用者ごとの権限分離と外部公開の検証は未対応のため、インターネットへ公開しない。

## 実行する範囲

AIはVMやデスクトップコンテナを操作する。バックエンドは環境管理のためにDockerソケットを使う。バックエンドが侵害された場合までホストの隔離を保証する構成ではない。

環境管理・タスクAPI・状態通知・画面配信は認証を必須とし、ブラウザのOriginも制限する。ブラウザにはHttpOnly・SameSite=StrictのセッションCookieを渡し、接続キーをブラウザの保存領域やURLに残さない。セッションは12時間、ログアウト、バックエンド再起動のいずれかで失効する。APIクライアントはAuthorizationのBearerで接続キーを送れる。

ログアウトでは送信されたCookieのセッションを取り消し、閲覧接続を閉じる。実行中のタスクを止めるには先に［停止］を選ぶ。セッションが失効している場合やCookieがない場合もログアウトは完了する。

初期画面の読み込みは操作を始める前に限り1回だけ自動でやり直す。読み込みの失敗が続く場合やブラウザの保存領域が使えない場合は［再読み込み］を選ぶ。

接続キーの照合失敗はログインとBearer認証で共通に数える。直近60秒に10回失敗すると新しい照合を一時制限し、HTTPでは429とRetry-Afterを返す。WebSocketも接続前に拒否する。Cookieで認証済みの操作とログアウトは使える。失敗数はバックエンドのメモリに保存し、再起動で消える。

HTTP本文は256 KiBまでとし、超過時は413を返す。5秒以内に受信できなければ408を返す。どちらの場合もタスクを作らず、受信途中の切断でもタスクは始めない。

タスクの送信は全接続で直近60秒に60件、受付処理中は8件までとする。再送と不正な本文も数える。超過時は本文を読まずに429とRetry-Afterを返す。停止操作・状態確認・ログアウトはこの制限に含めない。件数はバックエンドのメモリに保存し、再起動で消える。

WebSocketで受信する1メッセージは1 MiBまでとする。画面配信の終了時は受信処理を取り消して作業環境へのTCP接続を閉じ、接続終了の待ち時間も制限する。

VNC・ADBをホストへ直接公開せず、画面配信は認証付きプロキシを通す。旧版の中継は同じプロジェクトのものだけ起動時に撤去し、失敗した場合は起動を止める。既存環境に残るVNCの公開設定は、環境を再作成するまで残る。

管理用ネットワークと各作業環境の専用ネットワークを分ける。管理APIは管理用IPだけで待ち受け、送信元のネットワークも確認する。作業環境から別環境や管理APIへの接続を制限し、外部サイトへの接続は許可する。転送ヘッダーで送信元を偽装しても許可しない。

環境とネットワークは所属プロジェクトを確認して操作する。旧環境は保存済み情報と共有ネットワークの一致も確認し、専用ネットワークへ移す。移行や所属確認に失敗した場合は処理を止める。バックエンド再作成後は保存済み情報から接続を復元する。

コンテナデスクトップ1台の既定上限はCPU 2個分・メモリ2 GiB・プロセスとスレッドの合計1024とし、スワップは使わない。`.env`の`DESKTOP_CPUS`・`DESKTOP_MEMORY_MB`（MiB）・`DESKTOP_PIDS_LIMIT`で変更できる。メモリとプロセス数は正の整数、CPUは0.01以上を指定する。メモリは6 MiB以上が必要だが、作業に必要な容量も確保する。

設定変更後は`./scripts/up.sh`で既定desktopとバックエンドを更新する。追加した環境には新規作成時だけ適用し、既存環境には適用しない。上限に達するとアプリの終了や起動失敗が起きるため、作業を確認して上限を見直す。QEMU・Androidとディスク容量は対象外とし、複数環境の合計使用量がホストの容量を超えないようにする。

## 実行と停止

モデル応答の操作名、パラメータ、真偽値、確率を検査する。不正な操作や回復手順は実行せず、検証に失敗した応答を完了扱いにしない。決定モデルの確率が不正または不足している場合はLLMに確認する。

1タスクは回復操作を含めて200アクションまでとする。回復の再試行と再計画にも上限を設ける。同じ環境への後発タスクは先行タスクを停止するが、手動入力待ちでは新しいタスクを拒否する。別環境では並列実行できる。

実行時間には一時停止・手動入力・モデルの再試行を待つ時間も含む。再試行と決定モデルも送信回数・使用量に含む。上限に達した場合やモデル応答から使用量を取得できない場合は停止し、履歴に理由と使用量を残す。[実行時間・送信回数・使用量・推定費用の設定](../README.md#実行上限を変える)を参照する。

サブタスクの制限時間は既定で60秒。再試行・一時停止・手動入力でも延長せず、次のサブタスクや再計画を確定した時点で計り直す。期限切れの応答は操作や完了判定に使わない。1送信の応答待ちが期限切れの場合は、自動再試行にも使わない。モデルAPIが再試行までの待ち時間を指定した場合は、60秒以内なら待って再試行し、60秒を超えるなら停止する。

時間切れでは画面操作に停止を要求し、実行中の処理が終了してから接続を解放する。中断した操作は一部が実行された可能性も含めて履歴に残す。

実行中のVNC操作が10秒待っても応答を得られなければ、接続を閉じてタスクを失敗として終了する。途中まで入力された可能性があるため、デスクトップで結果を確認してから新しいタスクを実行する。

AIによる環境の再起動は `allow_vm_restart=true` の場合だけ実行する。再起動はディスクを初期化しない。Web UIからタスクの一時停止・再開・停止ができる。黒い画面を検出するとウェイクを試みる。

日本語や絵文字を含む入力は対象環境のクリップボードを置き換える。この入力処理から既存のクリップボードを取得する要求は送らない。非対応の接続や不正な文字列では入力前に失敗する。送信後に応答が途絶えた場合は、入力結果の確認を促すエラーを返す。

## 秘密情報を入力する

パスワードや認証コードは指示やAIの入力操作に含めず、手動で入力する。AIが `request_user_input` を選ぶと［手動入力待ち］になり、AI向けの画面取得とモデル呼び出しを止める。利用者が接続先を確認してデスクトップへ入力し、ログインなどを終えて秘密情報を画面から隠した後、［画面を送信して再開］を選ぶ。入力値をタスクAPIへ渡す項目はない。

再開には要求ごとのIDと画面送信の許可が必要で、古い要求や別環境のIDでは再開しない。待機中も時間の上限は進み、停止できる。任意の秘密情報、画面内の文字、デスクトップのファイル、ホームのバックアップは自動マスキングしない。再開や次のタスク投入の前に画面を確認する。

状態通知が切れると、画面からの入力と［画面を送信して再開］を無効にする。再接続して手動入力待ちを確認すると、操作できるようになる。再開・停止・時間切れでは押されたままのキーとマウスボタンを解放し、解放できなければタスクを終了する。

設定済みのAPIキー・接続キーなど、登録された8文字以上の値は、モデルに渡すテキスト、応答、履歴、通知、エラー、ログで `[REDACTED]` に置き換える。短い値や任意の秘密情報をすべて検出する仕組みではない。認証ヘッダーには接続に必要な実際の値を送る。

## 保存する情報

ブラウザの同じタブに再送用の識別子と照合用ハッシュを保存し、ページ再読み込み後の重複実行を防ぐ。指示の本文や接続キーは保存しない。受付結果の確認後とログアウト時に再送情報を消す。ブラウザの保存領域やWeb Cryptoを使えない場合は、ページを開いている間だけ再送情報を保持する。

再読み込み後に再送する場合は、同じ指示を入力し、同じ環境と再起動許可を選ぶ。再送情報を復元できない場合は、状態と履歴を確認してから再実行する。

操作、判断理由、時刻、処理時間、トークン使用量を履歴に保存する。AIが入力した文字列も含まれる。手動入力の値はタスク履歴に渡さないが、ログイン先のアプリには届く。保存先とバックアップのアクセスを制限する。

起動時に有効な既存履歴も確認し、保護対象の値が残るファイルを原子的に書き直す。破損した履歴は読み飛ばす。破損ファイルと既存のバックアップは書き換えない。

履歴を保存できなければタスクを止める。履歴の削除ではタスクの停止と保存処理の終了を待ち、削除結果をディスクへ同期してから成功を返す。同期失敗はエラーとして通知し、再試行ではファイルが既になくても同期を行う。VM情報の破損は上書きせずエラーを返す。固定QEMU VMと動的VMは、読み取り専用テンプレートから複製した専用ディスクを使う。

コンテナ環境のホームは環境ごとのボリュームに保存する。固定desktopの更新では旧コンテナを停止し、バックアップと移行先の照合を終えてから再作成する。旧版の動的環境は自動移行しない。

ホームのバックアップは `data/backups/プロジェクト名/` に0600で保存し、自動削除しない。ファイルの内容・所有者・アクセス権・リンクを照合する。復元には所属を確認した未使用のボリュームだけを使う。展開用コンテナにはネットワーク、Dockerソケット、ホストの保存先を渡さない。

ホーム外と未保存の作業、リンク先の外部ファイル、QEMU・Androidのディスクはホームのバックアップに含まれない。動的環境の削除ではディスクとホーム用ボリュームも削除する。[保存範囲と復元手順](workspace-backups.md)を確認する。

## 依存ライブラリとOS

Pythonとnpmの本番依存をロックファイルに固定し、CIで既知の脆弱性を監査する。検出時はCIを失敗させる。

backend・frontend・desktop・QEMU・Android起動用のコンテナは、ビルド時にOSパッケージを更新する。CIではOSの既知の脆弱性を監査し、修正版のある検出、サポート終了、監査失敗で停止する。週次でも実行し、修正版のない検出と除外前の結果を `os-audit` 成果物に30日間保存する。

Mozilla版FirefoxとUbuntuのSnap版の比較による誤検出は、[確認済みのCVEとバージョン](../security/trivyignore.yaml)だけを期限付きで除外する。Firefoxのバージョンを更新するときは根拠を再確認する。ゲストOS、同梱ライブラリの網羅的な検査、未知の脆弱性はこの監査の対象外とする。

### 2026年11月24日のHIGH検出

コミット `79d28d1` の本番5イメージで、修正版が提供されていないHIGHは重複を除いて14件だった。13件はbackendに、1件はQEMU・Androidの両方に含まれる。引き続き全件を監査する。[対象コミットのCIと監査結果](https://github.com/Milix-M/ai-desktop-agent/actions/runs/45411307581)

| 対象と件数 | アプリで確認した利用箇所 |
| --- | --- |
| backend の util-linux（4件） | イメージには `mount` と `nsenter` がある。作業環境のマウントとネットワークの設定にはDocker APIを使う。 |
| backend の SQLite（3件）・OpenSSL（2件） | PythonからSQLiteを使える。タスク履歴はJSON、ホームのバックアップはtarで保存する。モデルAPIとWebhookのHTTPS通信ではTLSを使い、今回のOpenSSLの検出対象であるQUICは使っていない。 |
| backend の libacl・ncurses（各1件） | libaclとncursesが含まれる。アプリのPythonコードは両者を直接呼び出していない。依存先を含む間接的な利用は未確認。 |
| backend の systemd・Perl（各1件） | backendには該当パッケージ由来のライブラリとPerl本体がある。arm64イメージで確認したところ、対象の `systemd-homed` 実行ファイルとPerlモジュール `Archive::Tar` は含まれていなかった。 |
| QEMU・Android の QEMU（共通の1件） | 対象はvirtio-gpu。両方の起動スクリプトでQEMU 8.2.2をTCG起動し、ゲストCPUを開始する前にQMPの `query-pci` で確認した。どちらの表示デバイスも標準VGA（PCI ID `1234:1111`）の1台だった。[Ubuntuの対象バージョン](https://ubuntu.com/security/CVE-2026-3886)・[QEMU標準VGAの仕様](https://www.qemu.org/docs/master/specs/standard-vga.html) |

イメージや起動時のデバイス構成を変更した場合は、新しい監査結果と実行環境を照合する。frontendのAlpine向け監査は、未修正の脆弱性を網羅しない。[TrivyのAlpine対応範囲](https://trivy.dev/docs/latest/coverage/os/alpine/)

## 残る課題

利用者ごとの権限分離、任意の秘密情報と画面のマスキング、危険操作の承認、アクションレート制限を追加する。請求実績との照合、QEMU・Androidのディスクをバックアップから復元する手順も残る。KVM上の両ゲストでは、コンテナ再作成後のデータ保持まで検査する。[本番利用に向けた確認事項](production-readiness.md)
