# 本番利用に向けた確認事項

ローカルの1人利用を基準にしています。外部公開や複数利用者での運用は、利用者ごとの権限と隔離を検証してから判断します。

| 項目 | 検査している範囲 | 残る確認・対応 |
| --- | --- | --- |
| 認証と隔離 | 接続キーの試行制限、ログイン状態の同期、実通信での環境間の遮断 | 利用者ごとの権限分離、外部公開、危険操作の承認 |
| タスクとモデル | 応答の型・座標・確率、完了確認、回復と再計画、実行上限、中断後の接続の解放 | 実モデルでの成功率の比較、アクションレート制限、推定費用と請求実績の照合 |
| 接続と画面 | 実VNCの入力と再接続、IPv6経由の画面取得、古い通知や履歴応答の除外、バックエンド再作成後の同期 | 複数環境の同時監視 |
| タスクと環境の再送 | バックエンド再作成後の重複防止、ブラウザ再読み込み後の受付確認、同じ環境の操作の排他 | 作成の受付記録の自動削除、複数バックエンドの同時運用 |
| QEMU・Android | QMPの接続・状態取得、実qemu-gaとの通信、qcow2からの起動ファイル取得、KVM上でのUbuntu・Android起動、Android初期設定とコンテナ再作成後のデータ保持 | 電源断からのVMイメージ構築の復旧 |
| データの保存 | 履歴・環境情報の保存失敗、停止・削除との競合、固定desktopのホーム移行・バックアップ・復元、同じ保存先の二重起動の拒否 | 旧追加環境の自動移行、QEMU・Androidのディスク復元、保存期間、電源断からの復旧、履歴の検索 |
| 秘密情報 | 登録済みキーの伏せ字、実ブラウザでの手動入力と再開 | 任意の秘密情報と画面の自動マスキング |
| 依存とOS | 本番用のPython・npm依存と5種類のコンテナのOSをCIで監査 | ゲストOSと同梱ライブラリの網羅的な監査 |
| 日本語入力 | コンテナの端末とエディタで日本語・絵文字の保存内容を確認 | QEMU・AndroidのUnicode入力 |
| 品質評価 | 4課題の成果物・所要時間・使用量を記録し、CIでは `scripted` で評価基盤を確認 | 定型タスクのテンプレート、決定モデルを有効にする前の評価 |

[安全性と運用上の制限](safety.md)、[テストとCI](testing.md)、[定型作業の評価手順](desktop-evaluation.md)、[実モデルでの比較結果](https://github.com/Milix-M/ai-desktop-agent/pull/90)を参照してください。

## 参考にした設計

実際に作成されたファイルでタスクの結果を検査する方法は、[Agent S](https://github.com/simular-ai/Agent-S)と[OSWorld](https://github.com/xlang-ai/OSWorld)を参考にしました。実行上限と秘密情報の扱いは、[Browser Use](https://github.com/browser-use/browser-use)を参考にしています。デスクトップでは入力先のドメインをプログラムで確定できないため、利用者が接続先を確かめて手動で入力します。

完了宣言と成果の確認を分ける設計は、[Browser Useの完了検証](https://github.com/browser-use/browser-use/blob/main/browser_use/agent/judge.py)と[OpenAIのComputer Useサンプル](https://github.com/openai/openai-cua-sample-app)を参考にしました。[Cua Bench](https://cua.ai/docs/cua-bench/quickstart)の課題・模範操作・評価の分離も、実デスクトップ検査で保存内容を確認する際に参考にしています。
