# 本番利用に向けた確認事項

ローカルの1人利用を基準に改善を進めます。外部公開や複数利用者での運用は、利用者ごとの権限と隔離を検証してから判断します。

| 項目 | 対応と残る確認 |
| --- | --- |
| モデル応答 | 不正な座標による誤クリック、未知の操作や文字列の真偽値による誤った完了判定、回復手順の一部だけの実行を防ぎます。NaN・無限大・範囲外の確率を拒否し、確率がない場合も値を補わずLLMに確認します。実モデルでの成功率比較は残ります |
| 接続と状態 | VNCの再接続、操作結果の分離、全環境の状態同期、古い通知の無視、遅い閲覧者による実行の遅延を修正済み。開始順を保存し、古いタスクの完了通知や遅れて届く復元・履歴の応答が新しい表示を上書きする問題を修正しました。通信失敗、状態配信の送信終了、VNC接続・セッション生成中の中断で接続や通知先が残る問題も修正しました。初期接続失敗と応答待ちは実VNC・TCPで検査します。実ブラウザで切断後の復旧も確認します |
| タスクの再送 | 応答が失われても同じ投入を照合し、操作の重複を防ぎます。同じタブの再読み込み後も識別子とハッシュを保持し、指示の本文は保存しません。履歴削除後は新規実行を明示的に選びます。実VNCでの操作回数、バックエンド再作成後の照合、ブラウザの再送を検査します。複数バックエンドでの排他は残ります |
| タスクの操作 | Web UIの一時停止・再開・停止を画面のタスクIDに結び付け、別のタスクへの誤操作を防ぎます。対象変更時は操作を拒否して最新状態を取得し、自動では再実行しません。後発タスク、手動入力、遅い状態取得を実VNCとブラウザで検査します |
| 履歴と状態の同期 | 履歴読取中の開始・終了・削除を同期へ反映します。最新タスクの削除後も再接続で残る履歴を表示し、削除済みタスクの通知を無視します。削除済み環境の履歴と旧履歴の表示を、環境一覧の更新後も保ちます。読み取りの重なり・取消・失敗を含めて検査します |
| 再起動後の表示 | 起動識別子で旧起動の応答・通知を除外します。古い開始順への復元、入力中の指示の保持、選択中の履歴の再取得はブラウザで検査します。起動識別子の変更は実バックエンドの再作成で検査します |
| ゲスト通信 | 接続時に古いデータを読み捨て、要求と返答を照合します。待ち時間と出力を制限し、出力の省略は例外で通知します。コンテナ内の実qemu-gaで検査し、QEMU上のゲストOS起動は未検証です |
| VNCの接続先 | Docker形式のASCII名とIPv6アドレスを扱います。名前解決中と接続待ちの段階で中断を検査します。アンダースコアを含むDocker名での実タスク投入と、IPv6のTCP中継による画面取得を検査します |
| タスク終了と回復 | 分解失敗・例外・一時停止中の停止で、失敗状態を保存して完了を通知します。回復操作の実行、残作業の再計画、再試行上限はテスト済みです |
| 環境管理 | 所属プロジェクトの照合、中継と本体の区別、共有マウント経由のディスク削除、Docker操作の失敗通知を追加しました。Dockerの照会失敗は503を返し、古い稼働状態で代用しません。動的環境で同じ環境IDの本体が複数ある場合も503で拒否します。再起動の応答が失われた場合は再操作前に状態を確認します。SDKを通してHTTP通信障害を検査し、実Dockerで一覧とデバッグ用再起動の対象の一致を確認します。明示した再起動先に合わせてタスクを停止します |
| Dockerの対象検索 | 一覧情報で所属を絞ってから詳細を取得し、別プロジェクトの詳細取得失敗に影響されないようにしました。一覧から詳細取得までの対象消失は除外し、旧環境は詳細取得後も所属を確認します。SDKのHTTP通信と実Dockerで一覧・片付け・ホームの使用確認を検査します |
| 環境操作の待ち時間 | 複製・停止・画面接続の待ちで別環境の操作まで待たせる問題を修正しました。同じ環境の操作は初回保存と中断後の後始末まで待たせます。既定環境の再確認、開始順、同じ投入キーの照合も検査します。作成には専用ワーカーを使い、新旧APIの実行中と待ちの合計が8件を超えると429を返します。実Dockerで複製と停止を待たせ、HTTP経由で検査します |
| 環境作成の再送 | 受付キーで同じ作成を照合し、応答が失われても環境を重複して作りません。起動時は未開始を再開し、開始済みは対象IDで照合します。保存失敗と同時再送をテストし、実Dockerでバックエンド再作成後の照合を検査します。ブラウザでも応答切断後の再読み込みとキーの保持を検査します。受付記録の自動削除は未対応です |
| 環境の準備 | 準備中・異常の環境へのタスク投入を拒否し、復旧後に受け付けます。準備中の画面配信は続けます。未対応のVM実行イメージは複製前に拒否し、複製用コンテナも失敗時に回収します。再起動の古い確認・失敗・確認期限を含め、API・実VNC・ブラウザで検査します |
| Android初期設定 | タスク開始と環境操作の前に設定を中断し、ADBプロセスを終了・回収します。画面・記録・接続先を同じ本体に揃え、設定中の本体変更・保存領域変更・照会失敗でも中断します。記録は原子的に保存し、通常のディスク書き込みでは再設定しません。実Dockerで名前解決、本体の入れ替え、完了記録と設定用プロセスの回収を検査します。実Androidでの確認は残ります |
| 実環境の検査 | Firefoxの描画、VNC入力後のファイル内容、更新と復元、QMPの状態取得をCIで検査します。QMPはTCGで再開・停止・再接続を検査し、ゲストOSとKVMは含みません。Composeは対応下限の2.33.1を使います。QEMUとAndroidのゲスト起動は追加検査が必要です |
| KVMの初回起動 | 設定とディスクを起動前に確認します。各ディスク内のカーネルとinitrdを読み出し、テンプレートの再構築後も対応を保ちます。実qcow2・ext4で読み出しと元ディスクの保持、実QEMUで使用中の読み出し拒否を検査します。ゲストOSとKVMの起動は未検証です |
| VMイメージの構築 | 作業領域を分けて同時構築を拒否し、完成後に出力を更新します。更新失敗では旧ファイルへの復元を試み、マウント解除や復元に失敗すると作業領域を残します。使用中の実マウントで削除を防ぐことを検査します。電源断からの復旧とゲストOSの構築・起動の確認は残ります |
| データ保全 | 履歴とVM情報を原子的に保存し、保存失敗では実行を止めます。保存が遅い場合のAPI応答、停止・削除の競合、破損履歴を検査し、一覧のメモリ使用量を抑えます。固定desktopのホーム移行、バックアップと復元、更新失敗後の再試行は実環境で検査します。旧動的環境の自動移行、QEMU・Androidのディスク復元、保存期間、電源断からの復旧、履歴が増えた場合の検索は残ります |
| 認証と隔離 | APIと配信を認証し、管理用と環境ごとにネットワークを分けます。接続キーの連続試行はログイン・Bearerで共通に制限します。実通信の遮断、再作成後の復旧、試行制限と復帰を検査します。利用者ごとの権限、危険操作の承認は残ります |
| ログイン状態 | 古い401・初回確認・切断済み接続の確認で、再ログイン後の状態を上書きしないようにしました。同時確認と認証変更の順序、別タブの変更、期限切れ後のログアウトをブラウザとAPIで検査します |
| 秘密情報 | 登録済みのキーをテキスト・履歴・ログでマスキングし、パスワードなどは画面送信を止めて手動入力を待ちます。実Firefoxで入力と再開を検査します。任意の秘密情報と画面の自動マスキングは残ります |
| 実行制限 | 時間・応答待ち・モデル送信回数・トークン・設定単価による推定費用を制限します。再試行と決定モデルにも適用し、期限切れと中断操作の保存を検査します。HTTP本文のサイズと受信時間も制限します。請求実績との照合、タスクAPIのレート制限は残ります |
| 日本語入力 | コンテナの既定ロケールをUTF-8にし、日本語・絵文字を貼り付けます。端末とエディタで保存内容をCIで検査します。QEMU・AndroidのUnicode入力は残ります |
| 品質評価 | 3課題の成果物・所要時間・使用量を保存する評価CLIを追加しました。CIではscriptedで基盤を検査します。実モデルの比較結果は未取得です。[評価手順](desktop-evaluation.md)でモデルと環境を固定して比較します |
| 使い勝手 | 定型タスクのテンプレートと複数環境の同時監視を検討します。決定モデルは評価結果を確認してから有効にします |

## 参考にした設計

[Agent S](https://github.com/simular-ai/Agent-S)と[OSWorld](https://github.com/xlang-ai/OSWorld)の評価方法を参考に、実際にできたファイルの内容を検査するテストを追加しました。

[Browser Use](https://github.com/browser-use/browser-use)の実行上限と秘密情報の扱いを参考にしています。モデルの再試行と決定モデルにも上限を適用します。デスクトップでは入力先のドメインをプログラムで確定できないため、秘密情報は利用者が接続先を確認して手動で入力します。

[Browser Useの完了検証](https://github.com/browser-use/browser-use/blob/main/browser_use/agent/judge.py)と[OpenAIのComputer Useサンプル](https://github.com/openai/openai-cua-sample-app)は、エージェントの完了宣言と成果の確認を区別しています。この考え方に沿って、不正な応答から完了へ進まないテストを追加しました。[Cua Bench](https://cua.ai/docs/cua-bench/quickstart)の課題・模範操作・評価の分離も参考に、既存の実デスクトップ検査で保存内容を確認します。
