# 本番利用に向けた確認事項

ローカルの1人利用を基準に改善を進めます。外部公開や複数利用者での運用は、利用者ごとの権限と隔離を検証してから判断します。

| 項目 | 対応と残る確認 |
| --- | --- |
| 接続と状態 | VNCの再接続、全環境の状態同期、古い通知の無視、遅い閲覧者による実行の遅延を修正済み。実ブラウザで切断後の復旧も確認します |
| タスク終了と回復 | 分解失敗・例外・一時停止中の停止で、失敗状態を保存して完了を通知します。回復操作の実行、残作業の再計画、再試行上限はテスト済みです |
| 環境管理 | 所属プロジェクトの照合、中継と本体の区別、共有マウント経由のディスク削除、Docker操作の失敗通知を追加しました |
| 実環境の検査 | Firefoxの描画、VNC入力後のファイル内容、更新と復元をCIで検査します。Composeは対応下限の2.33.1を使います。QEMUとAndroidの実機検査は追加が必要です |
| KVMの初回起動 | 設定とゲストファイルを起動前に確認します。テンプレートは読み取り専用とし、固定VMも専用ディスクを使います。実機起動は未検証です |
| データ保全 | 履歴とVM情報を原子的に保存し、保存失敗では実行を止めます。固定desktopのホーム移行、バックアップと復元、更新失敗後の再試行は実環境で検査します。旧動的環境の自動移行、QEMU・Androidのディスク復元、保存期間、電源断からの復旧、履歴が増えた場合の検索は残ります |
| 認証と隔離 | API・配信の認証に加え、管理用と環境ごとのネットワークを分離します。実通信の遮断とバックエンド再作成後の復旧をCIで検査します。利用者ごとの権限、危険操作の承認は残ります |
| 秘密情報 | 登録済みのキーをテキスト・履歴・ログでマスキングし、パスワードなどは画面送信を止めて手動入力を待ちます。実Firefoxで入力と再開を検査します。任意の秘密情報と画面の自動マスキングは残ります |
| 実行制限 | 時間・応答待ち・モデル送信回数・トークン・設定単価による推定費用を制限します。再試行と決定モデルにも適用し、期限切れと中断操作の保存を検査します。請求実績との照合、レート制限は残ります |
| 日本語入力 | コンテナの既定ロケールをUTF-8にし、日本語・絵文字を貼り付けます。端末とエディタで保存内容をCIで検査します。QEMU・AndroidのUnicode入力は残ります |
| 品質評価 | 実LLMによる定型作業の成功率・所要時間・使用量を測ります。モデルと環境を固定して比較します |
| 使い勝手 | 定型タスクのテンプレートと複数環境の同時監視を検討します。決定モデルは評価結果を確認してから有効にします |

## 参考にした設計

[Agent S](https://github.com/simular-ai/Agent-S)と[OSWorld](https://github.com/xlang-ai/OSWorld)の評価方法を参考に、実際にできたファイルの内容を検査するテストを追加しました。

[Browser Use](https://github.com/browser-use/browser-use)の実行上限と秘密情報の扱いを参考にしています。モデルの再試行と決定モデルにも上限を適用します。デスクトップでは入力先のドメインをプログラムで確定できないため、秘密情報は利用者が接続先を確認して手動で入力します。
