# AI Desktop Agent

![AI Desktop Agentのプロダクトイメージ](docs/images/readme-hero.png)

自然言語の指示で、VMやコンテナ内のデスクトップをAIが操作する。ブラウザで画面を見ながら、指示・一時停止・停止・履歴の確認ができる。

## 起動する

Docker Engine（API 1.48以降）とDocker Compose 2.34.0以降、画像入力に対応するモデルが必要になる。クラウドのモデルを使う場合はAPIキーを用意する。ローカルの1人利用を対象とする。

QEMU VMを使う場合は、x86_64ホストの `/dev/kvm` とゲストファイルが必要になる。先に `sudo ./vm/build-vm-image.sh` を実行する。このスクリプトはホストにパッケージを導入し、テンプレート `vm/desktop.qcow2` を作成する。

再構築しても既存VMのディスクは上書きせず、起動時に各ディスク内のカーネルとinitrdを読み出す。保存先には一時コピー用の空き容量が必要になる。読み出しに失敗すると元ディスクを変更せず起動を止める。構築失敗時は旧ファイルへの復元を試み、マウント解除や復元に失敗すると作業領域を残して保存先を表示する。

```bash
# 初回のみ。展開したフォルダーで実行する
(umask 077; cp -n .env.example .env)
realpath .env
# 表示されたファイルを開く。OpenAIを使う場合は OPENAI_API_KEY に自分のキーを設定する
./scripts/up.sh
```

初回起動で接続キーを生成する。次のコマンドで確認し、[http://localhost:3000](http://localhost:3000) のログイン画面に入力する。`.env` の `AGENT_ACCESS_TOKEN` を指定した場合は、その値を使う。

```bash
docker compose exec backend cat /app/data/auth/access-key
```

初期画面の読み込みに失敗すると1回だけ自動で読み直し、失敗が続けば［再読み込み］を表示する。ブラウザの保存領域を使えない場合も［再読み込み］を選ぶ。この自動処理は画面の操作を始める前に限る。

KVMとゲストファイルが揃う場合はQEMU VM、それ以外はXfceのコンテナが起動する。`.env` の `USE_KVM=false` でコンテナを選べる。`true` で条件が不足する場合は起動前に止まる。Androidは初期起動に含まない。

| 接続先 | ポート |
| --- | --- |
| 操作画面 | 3000 |
| API・状態通知・画面配信 | 8081 |

公開ポートはホストのループバックに限定する。API・状態通知・画面配信は認証を必須とし、VNC・ADBのポートを直接公開しない。旧版の中継は起動時に同じプロジェクトのものだけ撤去する。

各作業環境に専用ネットワークを割り当て、管理APIと別環境への接続を制限する。外部サイトへの接続と、認証後の画面配信は利用できる。

ログインは12時間有効で、バックエンド再起動後は再ログインする。ログアウトは閲覧接続を切断するが、実行中タスクは止めない。停止する場合は先に［停止］を選ぶ。

接続キーの照合に60秒以内で10回失敗すると、ログインとBearer認証を一時制限する。画面に表示する秒数を待ってから再試行する。ログイン済みのブラウザでは操作とログアウトを続けられる。

## 更新する

アプリ内の作業を保存してから `./scripts/up.sh` を実行する。更新中はバックエンドと選択した固定環境を停止する。ベースイメージを取得し直し、UTC日付が変わるとOSパッケージの更新も再実行する。

固定desktopでは `/home/agent` をバックアップし、旧コンテナのファイルを専用ボリュームへ移す。内容とアクセス権の照合に失敗した場合は再作成を止め、元のコンテナの再開を試みる。ホーム外のファイルと未保存の作業は対象外となる。

直接の `docker compose up` は移行処理を通らない。[バックアップと復元](docs/workspace-backups.md)に保存範囲と復元手順をまとめる。

## コンテナデスクトップをgVisorで動かす

[gVisorのDocker設定手順](https://gvisor.dev/docs/user_guide/quick_start/docker/)に従い、Dockerホストに `runsc` を登録する。アプリ内の作業を保存し、`.env` に `DESKTOP_RUNTIME=runsc` を設定して `./scripts/up.sh` を実行する。固定環境をコンテナにする場合は `USE_KVM=false` も設定する。

設定は固定desktopの再作成時と、［コンテナ追加］で新しい環境を作成するときに適用する。固定desktopのホームは更新手順で引き継ぎ、作成済みの追加環境は作成時のランタイムで動く。設定を省くとDockerホストの既定を使う。標準ランタイムを明示するには `DESKTOP_RUNTIME=runc` を指定する。

`runsc` の登録がない場合、`./scripts/up.sh` は環境を停止する前に終了し、追加コンテナの作成も失敗する。gVisorで隔離する対象は作業コンテナで、管理バックエンドは引き続きDockerソケットを使う。

## 指示を出す

環境のタブを選び、指示を入力して［実行］を選ぶ。Enterで送信、Shift+Enterで改行する。日本語変換中のEnterでは送信しない。

［準備中］［接続異常］の環境にはタスクを投入できない。

送信が混み合う場合は、画面に表示する秒数を待って［再送］を選ぶ。停止操作と状態確認は続けられる。

通信エラーでもタスクが受け付けられている場合がある。同じ指示・環境・再起動許可のまま［再送］を選ぶと、受付済みのタスクを返す。履歴が削除済みの場合は［新しいタスクとして実行］を明示的に選ぶ。

再送情報は同じタブの再読み込みや再ログイン後も保持し、受付結果の確認後とログアウト時に消す。指示の本文は保存しないため、再読み込み後は同じ指示を入力し、同じ環境・再起動許可で送信する。ブラウザの保存領域やWeb Cryptoを使えない場合は再読み込み後に照合できないため、状態と履歴を確認してから再実行する。

同じ環境への後発タスクは先行タスクを停止する。ただし、手動入力待ちでは新しいタスクを拒否する。別の環境では並列実行できる。1タスクは回復操作を含めて200アクションまでで、エラー回復にも再試行上限がある。再計画は3回までで、4回目は回復操作の実行前に打ち切る。

画像を拡大してもクリック位置を判断できない場合は、そのクリックを実行せず回復を試す。

［一時停止］［再開］［停止］は画面で確認した実行中タスクを対象とする。履歴の閲覧中も操作対象は実行中のタスクとなる。別のタスクに切り替わっていれば操作を拒否し、最新の状態を取得する。対象を確認してからもう一度操作する。 ［停止］後に返ったモデル応答は新しい入力・再起動・完了判定に使わない。

パスワードや認証コードは指示に書かず、AIに手動入力を求めるよう指示する。［手動入力待ち］になったら、接続先を確認してデスクトップへ直接入力する。ログインなどを終え、秘密情報を画面から隠して［画面を送信して再開］を選ぶ。待機中はAI向けの画面取得とモデル呼び出しを止める。時間の上限は進み、［停止］も使える。状態通知の切断を検出するとデスクトップへの入力と［画面を送信して再開］を止め、再接続後に手動入力待ちを確認してから有効にする。

デスクトップへの手動入力は、画面に古い状態が残っていても手動入力待ちの間だけ受け付ける。再開・停止・時間切れでは押したままのキーとマウスボタンを解除し、解除で通信エラーが起きるとタスクを終了する。

任意の秘密情報や画面内の文字を自動で隠す機能はない。再開や次のタスク投入の前に画面を確認する。[保護する情報と制限](docs/safety.md#秘密情報を入力する)を確認する。

［VM再起動を許可する］を選ぶと、AIの判断で環境を再起動できる。再起動はディスクを初期化しない。VNCと状態通知は切断後に再接続し、各環境の状態を同期する。バックエンドの再起動後は状態を同期し直し、選択中の履歴を再取得する。入力中の指示は残す。

デバッグの［VM再起動］は完了の確認を10分で打ち切る。期限後も再起動処理が続く場合があるため、状態を確認してから操作する。追加VMで実行イメージの更新を求められたら、`./scripts/up.sh` で更新する。`VM_IMAGE_REF` を指定している場合は、対応するイメージへ更新する。

追加環境のイメージを既定環境から検出する場合は、検出したバージョンに固定する。検出処理でエラーが起きた場合は作成を止める。

作成記録に矛盾やJSONの重複キーがある場合は作成を止め、元の記録を残す。保存先とバックアップを確認してからバックエンドを再起動する。

保存先の自動検出にはVMの追加ディスクとAndroidの起動ファイルに対応するbindマウントを使う。保存先を確認できない場合は作成を止める。`VM_HOST_DIR` はホスト側のリポジトリの絶対パス、`ANDROID_ISO_HOST` はISOファイルのホスト側の絶対パスで指定する。

タブの停止・起動は固定環境と追加した環境の両方に使える。本体の重複や不明な種別を検出すると、追加環境の起動・再起動を止める。対象環境の構成を確認してから操作する。動的環境を削除すると、その環境のディスクとホーム用ボリュームも削除する。固定環境の削除では保存先を残す。履歴の削除は作業ファイルを消さない。削除済み環境の履歴も閲覧できる。履歴の閲覧中は環境一覧を定期更新しても閲覧先を変えない。別の環境へ移るときはタブを選ぶ。

## 日本語を入力する

`./scripts/up.sh` で更新した固定desktopと、その後に追加したコンテナでは、日本語や絵文字を入力できる。旧版で追加した環境は自動再作成しない。

日本語などを含む入力は作業環境のクリップボードを置き換えて貼り付ける。1回の上限はUTF-8で64 KiBとし、改行・タブも文字として貼り付ける。端末ではコマンドを貼り付けた後にEnterで実行する。

貼り付けの応答がない場合や不正な場合は接続を閉じて操作を止める。入力結果を確認してから次の指示を出す。

選択した文字を置き換える場合は、Backspaceで削除してから入力する。クリップボードの更新で選択が解除される場合があるため、AIにもこの手順を指示する。

QEMU・AndroidのUnicode入力は未対応となる。非対応の接続では文字列を途中まで入力せずエラーを返す。

## LLMを選ぶ

`.env` の `LLM_PROVIDER`、`LLM_MODEL`、対応するキーで切り替える。モデルは画像入力に対応するものを選ぶ。

| LLM_PROVIDER | キー |
| --- | --- |
| `openai` | `OPENAI_API_KEY` |
| `anthropic` | `ANTHROPIC_API_KEY` |
| `openrouter` | `OPENROUTER_API_KEY` |
| `opencode` | `OPENCODE_API_KEY` |
| `opencode-go` | `OPENCODE_GO_API_KEY` |
| `ollama` | 不要 |

Ollamaを使う場合は、Ollamaを動かす環境で `ollama pull qwen2.5vl:3b` を実行し、アプリの `.env` に `LLM_PROVIDER=ollama` を設定する。別の画像対応モデルを使う場合は、取得したモデル名を `LLM_MODEL` に指定する。

`OLLAMA_BASE_URL` には、バックエンドから接続できるOllamaのURLを `/v1` まで指定する。たとえば同じCompose管理ネットワークに `ollama` というサービスがある場合は `http://ollama:11434/v1` を使う。省略時の `http://localhost:11434/v1` はバックエンド自身を指す。

モデル応答の型、サブタスクIDの重複、保存できない文字を検査し、問題があれば操作や完了判定に進まず履歴に理由を残す。

モデルAPIの認証エラーや再試行しても解消しないエラーでは、完了確認中もタスクを停止し、履歴に理由を残す。

## 実行上限を変える

次の上限は `.env` に正数で指定する。時間には一時停止中と手動入力中の待機も含み、モデルの再試行と決定モデルも送信回数・使用量に含む。

| 設定 | 既定の上限 |
| --- | --- |
| `TASK_MAX_SECONDS` | 1800秒 |
| `TASK_REQUEST_TIMEOUT_SECONDS` | 1送信の応答待ち120秒 |
| `TASK_MAX_REQUESTS` | 500送信 |
| `TASK_MAX_TOKENS` | 入出力合計100000トークン |

応答待ちの上限を越えた応答やエラーでは、取得済みの内容を操作・完了判定・自動再試行に使わない。

サブタスクにも制限時間がある（既定60秒）。再試行や一時停止・手動入力待ちでも延長せず、次のサブタスクや再計画の確定時に計り直す。期限後のモデル応答では操作や完了判定に進まない。

モデルAPIが再試行までの待機を指定した場合は、60秒以内ならその時間を待ち、60秒を超えれば再送せず停止する。待機時間も実行時間に含み、［停止］も使える。

推定費用を制限する場合は、`TASK_MAX_COST_USD` と入力・出力100万トークン当たりのUSD単価 `TASK_INPUT_USD_PER_MILLION`、`TASK_OUTPUT_USD_PER_MILLION` を設定する。複数モデルを使う場合は、各モデルの単価を下回らない値を指定する。

上限に達すると失敗として終了し、履歴に理由と使用量を残す。使用量を返さないモデル応答でも停止する。実行中の操作は終了を待つ場合がある。

使用量は応答後に加算するため、トークンと推定費用は1送信分超過する場合がある。未報告の失敗分や料金体系の差により、推定費用と請求額は異なる場合がある。

## 履歴を保存する

計画・完了確認・回復の失敗や上限到達、［停止］でタスクを終了すると、履歴に理由を残す。終了を通知している間に［停止］を選んでも、確定済みの結果は変わらない。

タスクと操作記録は `data/tasks/`、追加環境の情報は `data/vms.json` に保存する。バックエンド再起動時に残っていた実行中タスクは中断扱いになる。保存先に書き込めなければ起動・タスク投入を止め、実行中の保存失敗でも操作を打ち切る。空き容量とアクセス権を確認する。

環境情報に不正な値がある場合は、環境の準備・起動・停止・再起動・削除を止めて元のファイルを残す。保存先とバックアップを確認してから再操作する。

タスクの開始順は `data/task-order.json` に保存し、履歴と一緒に保管する。ファイルがなければ履歴に残る開始順の最大値から再開し、破損していれば新しいタスクを止める。

再送の照合に使う受付記録は `data/submissions/` に保存し、履歴と一緒に保管する。履歴を削除しても受付記録は残り、同じ投入の再実行を防ぐ。受付記録には指示と投入キーの原文を保存せず、ハッシュとタスクIDを保存する。

同じ保存先を使うバックエンドの二重起動は、履歴や環境を変更する前に拒否する。既存のバックエンドを停止してから起動する。

これらのデータを復元するときはバックエンドを停止し、復元後に再起動する。

固定QEMU VMの作業は `vm/instances/default.qcow2`、動的VMは `vm/overlays/` に保存する。`vm/desktop.qcow2` は読み取り専用のテンプレートとなる。履歴とディスクのバックアップには入力内容が含まれるため、取り扱いに注意する。

固定desktopと新しく追加するコンテナ環境は、環境ごとのボリュームに `/home/agent` を保存する。旧版で追加した動的環境は自動移行しないため、再作成前にホームをバックアップする。

## 開発時に確認する

Python 3.12以降・uv・Node.js 24が必要になる。対象を絞ったテスト、依存監査、CIの実行条件は[テストとCI](docs/testing.md)を参照する。

```bash
uv sync --frozen
uv run --frozen pytest -q -m 'not desktop_integration'
uv run --frozen ruff check src/ tests/ scripts/ci_scope.py
uv run --frozen ruff format --check src/ tests/ scripts/ci_scope.py
cd frontend
npm ci
npm test
npm run lint
npm run typecheck
npm run build
```

実デスクトップの確認はリポジトリのルートで実行する。LLMのAPIキーは使わず、Firefoxの描画、VNC入力後のファイル内容（日本語・絵文字・長文）、手動入力中の待機と明示的な再開、環境間の通信遮断、バックエンド再作成後の復旧、更新後のファイル保持、バックアップの復元を検査する。LLMの判断精度を測るテストではない。

```bash
docker build -t ai-desktop-agent-desktop-smoke desktop
docker build -t ai-desktop-agent-backend-smoke .
docker build -t ai-desktop-agent-qmp-smoke vm
docker build -t ai-desktop-agent-qga-smoke -f tests/integration/qga.Dockerfile .
docker build -t ai-desktop-agent-frontend-smoke frontend
RUN_DESKTOP_SMOKE=1 uv run pytest -m desktop_integration tests/integration/
```

CIでは対応下限のCompose 2.34.0で実デスクトップを検査する。通常の単体テストではこの検査をスキップする。

モデルの比較手順と結果の見方は[定型作業を評価する](docs/desktop-evaluation.md)を参照する。
